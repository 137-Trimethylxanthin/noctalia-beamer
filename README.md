# Fiaker

A calendar for [Noctalia](https://noctalia.dev) v5 that keeps the **month grid**
and the **day timeline** as separate widgets, and keeps them in sync — plus a
combined panel and a "next event in 25 min" bar widget.

Named after the Viennese coffee — and the carriage that gets you places on time.

This repository is a **Noctalia plugin source**. Add it once and the plugin shows
up in the plugin store like any other, updates included.

## Install

```sh
noctalia msg plugins source add fiaker git https://github.com/137-Trimethylxanthin/noctalia-fiaker
noctalia msg plugins enable 137-trimethylxanthin/fiaker
```

`source add` clones the repo into Noctalia's plugin cache; `enable` exports the
plugin and starts it. Both are also available in **Settings → Plugins**, where
`https://github.com/137-Trimethylxanthin/noctalia-fiaker` goes in under *Sources
→ Add*.

To pick up a new version later:

```sh
noctalia msg plugins update fiaker
```

## After installing, point it at a calendar

Fiaker ships **empty** until it has a source of events, and the default
`vdir_path` of `~/.calendars` is a guess, not a promise. Noctalia's plugin API
does not expose the built-in calendar, so on stock Noctalia 5.1.0 the working
backend is a directory of `.ics` files — the layout `vdirsyncer` produces.

In **Settings → Plugins → Fiaker**, set **vdir path** to that directory. If you
do not have one yet, `vdirsyncer` will sync Google or any CalDAV account into
one; point Noctalia's own calendar account at the same directory and the two can
never disagree.

`source = native` is reserved for a core API that does not exist yet; leaving
`source` on `auto` falls back to vdir until it does.

Full documentation — every widget, the settings, the now-line, testing, and the
reasoning behind the two backends — is in **[`fiaker/README.md`](fiaker/README.md)**.

## Repository layout

```
fiaker/           the plugin itself; this is what Noctalia exports
  plugin.toml     manifest: id, entries, plugin-level settings
  *.luau          the five entry scripts
  lib/            date math, model, layout, the two event sources
  translations/   en / de strings for every label_key
  README.md       the plugin's page in the store
  PROPOSAL.md     the design doc behind it
test/             pure-logic tests; not shipped to Noctalia
catalog.toml      source index; regenerated by CI on every push
```

`catalog.toml` is what makes the git route work: Noctalia reads it to render and
compat-check the source before cloning anything else. It is generated from
`fiaker/plugin.toml` by `.github/workflows/update-catalog.py` and committed, so
bumping `version` in the manifest is all a release takes. To regenerate it by
hand:

```sh
python3 .github/workflows/update-catalog.py
```

## Developing

Point Noctalia at your checkout instead of at GitHub — a `path` source is scanned
directly, with no catalog involved, and `.luau` edits hot-reload:

```sh
noctalia msg plugins source add dev path ~/Documents/code/noctalia-fiaker
noctalia plugins lint fiaker
./test/run.sh
```
